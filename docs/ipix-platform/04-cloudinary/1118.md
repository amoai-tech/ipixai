# IPI-1118 · SHOOT-ASSETS-001 — Attach Uploaded Assets to the Correct Saved Shoot

## Purpose

Make Shoot Detail read the canonical V2 relationship already persisted in Postgres: `public.assets.v2_shoot_id → shoot.shoots.id`. Do not create a second attachment model or use Cloudinary search/tags as shoot-membership truth.

## Faster/better approach

Reuse the existing signed upload context, webhook persistence, `public.assets.v2_shoot_id`, Shoot Detail RPC/UI, and IPI-1112 signed preview path. The smallest fix is the existing read path, not new attachment infrastructure.

## Acceptance criteria

- Shoot A returns assets whose `public.assets.v2_shoot_id` is Shoot A.
- The same asset is absent from Shoot B.
- Another organization cannot read Shoot A or its assets.
- `shoot.shoot_assets` is not populated as a second source of truth.
- Secure previews continue through the existing authorized Cloudinary preview path.
- Targeted SQL/DAL/UI tests and exact-head CI pass.
