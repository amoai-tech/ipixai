# Changelog

All notable verified changes to iPix are recorded here. This file follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Changed

- IPI-1389 · COPILOTKIT-UPGRADE-002 — Upgraded the CopilotKit/AG-UI half of the Planner runtime to `@copilotkit/runtime`/`@copilotkit/react-core` `1.85.0`, `@copilotkit/channels` `0.12.0`, `@ag-ui/client`/`@ag-ui/core`/`@ag-ui/encoder`/`@ag-ui/proto` `1.0.2`, and `@ag-ui/mastra` `2.0.2`, with Mastra deliberately held at `1.71.0` for this task. AG-UI is pinned to `1.0.2` because `@copilotkit/runtime@1.85.0` depends on exactly that version; `1.0.4` would install a second copy. The four `@ag-ui/*` `overrides` moved in the same commit — leaving them at `0.0.59` makes `npm install` fail with `EOVERRIDE`. `@ag-ui/core` is now a declared dependency because the tests import it directly. Runtime pin tests, the canonical `docs/mastra/runtime-family.md` table and the CopilotKit skill references were updated to match; `npm test` (1922 passed, 3 skipped), `tsc --noEmit` and `next build` are green. Follow-up tests confirmed and corrected CopilotKit 1.85's owner-scoped thread queries in `TenantAbortRunner`, strengthened the lockfile single-AG-UI-copy check, and removed retired version claims from the overview. No Mastra package, database schema, migration or deployment changed.

### Fixed

- IPI-1389 · COPILOTKIT-UPGRADE-002 — Closed the review gaps in the CopilotKit 1.85 ownership work. `TenantAbortRunner.connect()` now refuses a caller that names a different `ownerId` before any live replay or durable-history fallback; the remote-Stop owner callback forwards the run's `ownerId` into `stopLocal()` so the parent runner's Stop check cannot fall back to the server owner; and `getThreadState()` reads the parent event list directly because `super.getThreadState()` re-enters the overridden `getThreadEvents()` and would prefix the already-scoped thread id twice (every state read returned `null`). Tests now cover owner vs foreign message reads, owner vs foreign state reads, reconnect to a live run (owner receives `RUN_FINISHED`, foreign receives nothing), remote-Stop owner propagation, and the forwarding identity for `getThreadMessages`/`getThreadEvents`. `npm test` is 1927 passed / 3 skipped.
- IPI-1389 · DEPENDENCY-SECURITY-001 — Pinned every `undici` copy to `8.12.4` via `overrides`. The previous tree carried `undici@5.29.0` under `@ai-sdk/google-vertex` and `@ai-sdk/openai-compatible` (plus the bundled `@fastify/busboy@2.1.1`) and `undici@6.28.1` at the root, all inside the advisory range (`4.0.0–6.29.0`, `8.0.0–8.12.1`). The override removes both vulnerable copies and the nested busboy; `npm audit` drops from 90 to 70 findings and 49 to 36 high-severity findings, with `undici` and `@fastify/busboy` no longer reported. Remaining criticals (`next`, `dompurify`, `concurrently`, `proxy-addr`, `shell-quote`) are identical on `origin/main` and are not introduced by this PR.

### Added

- IPI-1294 / PR #258 — Standardized Linear workflow governance with mandatory four-template routing, documented exception and outage-handoff paths, clear `todo.md`/changelog ownership, and regression tests for the governance contract.
- IPI-1050 · MEM-001 — Proved Planner conversation continuity is durable rather than process-local: prior normal message history reaches the next same-thread model call after a real process restart, a thread-only fact does not leak into another thread of the same resource, and the fact arrives as message history rather than resource-scoped Working Memory. Adds `tests/mem-001-message-history.test.ts`, `scripts/mem-001-restart-proof.mjs`, and the `mem-001-restart-history` CI gate wired into the Production release dependencies.
- PR #302 — Made human approval for the exact head SHA a mandatory merge gate. An agent may open, update, review and fully prepare a pull request but never merges one; merging requires explicit human approval for that same head, the pre-merge checklist reviewed against verified current-head evidence with no item silently unchecked, deleted or weakened, and the success criteria reviewed the same way. Green CI is the precondition for asking, not a substitute for approval.
- PR #303 — Required safe local-`main` synchronization before creating the next task branch. `git fetch origin --prune` must succeed and `main...origin/main` must read `0 0`; local-only commits are preserved on a branch rather than silently reset, and an unverifiable `0 0` is never treated as synchronization.
- PR #305 — Encoded four merge-time practices into the tasks standard: durable records (`changelog.md`, `docs/**`, stale handoffs and trackers) are updated in the same PR as the change rather than as a follow-up; contract tests are run after editing any file they read; doc-contract assertions pin structure rather than transient prose; and a suggested cross-reference is opened and verified before it is cited.
- IPI-1370 · AGENT-DOCS-001 — Added `tests/agent-docs-contract.test.ts`, which fails when `AGENTS.md` or `CLAUDE.md` references a repository path or an `npm run` script that no longer exists, when a machine-local absolute path reappears in `AGENTS.md`, when `CLAUDE.md` restates a section `AGENTS.md` owns, or when the merge-authority rule loses its "no agent-side override" clause.
- IPI-1371 · SKILLS-001 — Added three skill-integrity guards. `scripts/skills-vendor-baseline.mjs` records a repository-owned tree hash for each of the 22 vendored skill trees and fails the build when one is edited in place, which `skills-lock.json`'s `computedHash` could not do because its algorithm lives in the external vendoring tool; `scripts/skills-reference-anchors.mjs` fails when a same-file markdown anchor points at no heading, verified against `github-slugger` across 16,046 headings with zero mismatches; and `tests/skill-frontmatter-contract.test.ts` fails when a `SKILL.md` frontmatter block is not valid YAML or its `name`/`description` breaks the Agent Skills spec — the unguarded class that let a `: ` inside this PR's own rewritten `playwright-cli` description make the skill unloadable while every other guard stayed green. Also recorded the skill-validation policy as ADR 005.
- PR #308 — Synced the CopilotKit and Mastra skill guidance to the installed in-process Planner runtime and added the guards that keep it there. `tests/skill-trigger-evals.test.ts` requires a `trigger-eval.json` with at least three should-trigger and three should-not-trigger queries per covered skill, so a rewritten skill description cannot be merged without evidence that it still routes. `tests/skill-contracts.test.ts` now covers `@mastra/client-js` in the documented package family, and the documented route handlers are derived from the real route (`src/app/api/copilotkit/[[...slug]]/route.ts`) rather than hand-pinned — the follow-up to #308 recorded here, because pinning only `GET` and `POST` left `PATCH` and `DELETE` deletable with the guard still green, which is the same "route exists and never runs" defect that guard was added to catch.

- IPI-1368 · DOC-PINS-001 — Added a drift guard for documented runtime pins. It fails when a row of `docs/mastra/runtime-family.md` disagrees with the installed package, and when `docs/prd.md`'s stack-truth section or `github/mastra/mastra-repos.md`'s preamble restates a version instead of pointing at that table. Scoped deliberately: `mastra-repos.md` legitimately records upstream versions it is *not* on (`mastra-ai/ui-dojo` "uses Core `1.50.0` and CopilotKit `1.62.1`, not the iPix family"), so the rule applies only where the document speaks for iPix. A second test asserts both guarded regions were actually located, so renaming a heading cannot make the assertion vacuous.

- PR #308 — Corrected the documented CopilotKit/Mastra runtime contract, which still described an older runtime shape. The route snippet now shows the Vercel adapter (`handle(app)` from `hono/vercel`) and all four App Router handler exports, where following it literally previously produced a route that existed and never ran. `mastra.md` is the single source of truth for the runtime contract and `ipix-v2-conventions.md` defers to it, removing two copies that could drift apart. The test helper `readMarkdownTree` resolves paths with `path.relative` instead of slicing `process.cwd()`, and throws `Skill tree not found: <path>` on a renamed or deleted tree instead of a bare `ENOENT`, so a contract can no longer pass by silently scanning nothing.
- IPI-1370 · AGENT-DOCS-001 — Corrected the agent contract files. `AGENTS.md` no longer documents `supabase start` as a working default (it fails with `failed to parse config: missing private key`, caused by the dotenvx-encrypted `.env.local`), and states the scope precisely: this is a local-environment defect, not a repository-wide one, since CI has no `.env.local` and the `supabase-fresh-replay` job runs the real `supabase start` plus `supabase db reset --local` path successfully on every pull request. It now records the bisected cause and two verified workarounds. Removed a machine-local absolute path from the portable format, documented the full precedence chain including the nested `AGENTS.md` files that already exist, documented that `npm test` runs `pretest: secrets:check` while `npx vitest run` bypasses it, added a path for when Linear's template field is unreachable from the available tooling, documented the assign-then-rename issue-identifier procedure, flagged the PR title check as machine-enforced, stated Graphify's user-local prerequisite, and added a rule for stray `.env.keys` backups. `CLAUDE.md` was reduced to its genuinely Claude-specific delta (goal, launch boundary, built-in accelerators, skill authoring, response-style delta) with pointers to `AGENTS.md` for the 13 repository-wide sections it had duplicated; its PR #106-gated instruction was corrected to record that the follow-up is outstanding, not historical. `.gitignore` now covers `/.kilo/`, which had been excluded only by the unshared `.git/info/exclude`.
- IPI-1371 · SKILLS-001 — Repaired 22 pre-existing broken same-file anchors across the skill references (hand-written table-of-contents entries using a simplified slug convention), gave three skill descriptions the when-to-use trigger they lacked so the skill is actually consulted, moved the subagent-driven-development worked example and rationalization table into `references/` to bring `SKILL.md` inside the progressive-disclosure budget, added tables of contents to 34 reference files over 300 lines, fixed a `playwright-cli` description whose unquoted `: ` made the skill's frontmatter unparseable, and deleted a reference file that was a byte-identical duplicate of an indexed sibling, was referenced by nothing, and whose name began with a space.
- IPI-1371 · SKILLS-001 — Corrected a real navigation bug the new anchor guard could not see: `mermaid-diagrams/references/c4-diagrams.md` pointed its **Container** section at `#basic-syntax-2`, which is the **Component** heading, so that link opened the wrong section. Three sections share the heading `Basic Syntax`; GitHub's slugs are `basic-syntax`, `basic-syntax-1`, `basic-syntax-2` in document order. Existence-checking accepted the link because the anchor does exist — just not for that section. A repo-wide scan found no other instance of this class.
- IPI-1371 · SKILLS-001 — Hardened the three skill guards after review, because each had a false-negative or false-positive path that let the class of defect it exists to catch slip through. `headingSlugSet` now bumps a duplicate suffix until the slug is free, matching `github-slugger`: for `Foo`, `Foo`, `Foo-1` it yields `foo`, `foo-1`, `foo-1-1`, where a one-shot counter reused `foo-1` — accepting a link to an id no heading owns and rejecting one GitHub really creates. Fence handling now tracks marker family and length, so four-backtick and tilde fences no longer invent headings and anchor-like text inside fenced examples is no longer read. Vendored trees are excluded by real path, which the `.claude/skills/<name>` → `.agents/skills/<name>` symlink had silently defeated for 6 of the 10 vendored roots (423 → 414 files scanned). Reference-pack discovery inspects every markdown file and requires them to agree instead of reading only the alphabetically first, so it no longer depends on which file sorts first — and unanimity rather than "any" is deliberate, since one upstream file beside iPix-authored siblings (`.claude/skills/ipix-supabase/references/`) must not freeze the whole directory. `skills:vendor:check` now compares against the committed baseline and exits non-zero on drift instead of printing and passing.
