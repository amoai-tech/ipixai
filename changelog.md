- IPI-1387 · GENUI-CATALOG-001 — Added the first read-only native CopilotKit Generative UI catalog and one named Planner surface. `ConceptComparison` shows two or three qualitative shoot concepts inside the existing provider, rejects quantified/status business claims in model-supplied text, refuses unknown components and malformed props with an accessible recovery message, and leaves existing chat, plan cards and HITL review unchanged. No Supabase, API or new dependency; the optional MapLibre 5.x import is aliased away because the catalog has no map, and live paid-AI rendering certification remains IPI-1427/IPI-1430 work.
- IPI-1420 · COPILOTKIT-SKILL-002 — Adapted the official CopilotKit v3.2.0 live-doc/source lookup skill in one iPix-owned entry, preserved Planner tenant/HITL boundaries, updated upstream skill inventory, corrected outdated v1 migration package advice and clarified four MCP corpora plus optional CLI safety. Added three focused load-on-demand guides for native catalogs/standardUI, page surfaces and AG-UI/A2UI 1.0 vs legacy dynamic-schema v0.9. No runtime/dependency/deployment changes.

- IPI-1294 / PR #258 — Standardized Linear workflow governance with mandatory four-template routing, documented exception and outage-handoff paths, clear `todo.md`/changelog ownership, and regression tests for the governance contract.
- IPI-1050 · MEM-001 — Proved Planner conversation continuity is durable rather than process-local: prior normal message history reaches the next same-thread model call after a real process restart, a thread-only fact does not leak into another thread of the same resource, and the fact arrives as message history rather than resource-scoped Working Memory. Adds `tests/mem-001-message-history.test.ts`, `scripts/mem-001-restart-proof.mjs`, and the `mem-001-restart-history` CI gate wired into the Production release dependencies.
- PR #302 — Made human approval for the exact head SHA a mandatory merge gate. An agent may open, update, review and fully prepare a pull request but never merges one; merging requires explicit human approval for that same head, the pre-merge checklist reviewed against verified current-head evidence with no item silently unchecked, deleted or weakened, and the success criteria reviewed the same way. Green CI is the precondition for asking, not a substitute for approval.
- PR #303 — Required safe local-`main` synchronization before creating the next task branch. `git fetch origin --prune` must succeed and `main...origin/main` must read `0 0`; local-only commits are preserved on a branch rather than silently reset, and an unverifiable `0 0` is never treated as synchronization.
- PR #305 — Encoded four merge-time practices into the tasks standard: durable records (`changelog.md`, `docs/**`, stale handoffs and trackers) are updated in the same PR as the change rather than as a follow-up; contract tests are run after editing any file they read; doc-contract assertions pin structure rather than transient prose; and a suggested cross-reference is opened and verified before it is cited.
- IPI-1370 · AGENT-DOCS-001 — Added `tests/agent-docs-contract.test.ts`, which fails when `AGENTS.md` or `CLAUDE.md` references a repository path or an `npm run` script that no longer exists, when a machine-local absolute path reappears in `AGENTS.md`, when `CLAUDE.md` restates a section `AGENTS.md` owns, or when the merge-authority rule loses its "no agent-side override" clause.
- IPI-1371 · SKILLS-001 — Added three skill-integrity guards. `scripts/skills-vendor-baseline.mjs` records a repository-owned tree hash for each of the 22 vendored skill trees and fails the build when one is edited in place, which `skills-lock.json`'s `computedHash` could not do because its algorithm lives in the external vendoring tool; `scripts/skills-reference-anchors.mjs` fails when a same-file markdown anchor points at no heading, verified against `github-slugger` across 16,046 headings with zero mismatches; and `tests/skill-frontmatter-contract.test.ts` fails when a `SKILL.md` frontmatter block is not valid YAML or its `name`/`description` breaks the Agent Skills spec — the unguarded class that let a `: ` inside this PR's own rewritten `playwright-cli` description make the skill unloadable while every other guard stayed green. Also recorded the skill-validation policy as ADR 005.
- PR #308 — Synced the CopilotKit and Mastra skill guidance to the installed in-process Planner runtime and added the guards that keep it there. `tests/skill-trigger-evals.test.ts` requires a `trigger-eval.json` with at least three should-trigger and three should-not-trigger queries per covered skill, so a rewritten skill description cannot be merged without evidence that it still routes. `tests/skill-contracts.test.ts` now covers `@mastra/client-js` in the documented package family, and the documented route handlers are derived from the real route (`src/app/api/copilotkit/[[...slug]]/route.ts`) rather than hand-pinned — the follow-up to #308 recorded here, because pinning only `GET` and `POST` left `PATCH` and `DELETE` deletable with the guard still green, which is the same "route exists and never runs" defect that guard was added to catch.

- IPI-1368 · DOC-PINS-001 — Added a drift guard for documented runtime pins. It fails when a row of `docs/mastra/runtime-family.md` disagrees with the installed package, and when `docs/prd.md`'s stack-truth section or `github/mastra/mastra-repos.md`'s preamble restates a version instead of pointing at that table. Scoped deliberately: `mastra-repos.md` legitimately records upstream versions it is *not* on (`mastra-ai/ui-dojo` "uses Core `1.50.0` and CopilotKit `1.62.1`, not the iPix family"), so the rule applies only where the document speaks for iPix. A second test asserts both guarded regions were actually located, so renaming a heading cannot make the assertion vacuous.

- IPI-1374 · REPO-HYGIENE-001 — Closed the Claude-only skill migration backlog. All 17 remaining real directories moved from `.claude/skills/<name>/` to the canonical `.agents/skills/<name>/` home and are re-exposed as relative `.claude/skills/<name>` symlinks, so each of the 53 skills now has exactly one real copy and every one is registered. `skills-vendor-baseline.json` is byte-identical before and after, which proves the move relocated vendored trees rather than editing them, and `claudeOnlySkillNames()` is now empty, so the registry's canonical set and the tree can no longer disagree.
- IPI-1374 · REPO-HYGIENE-001 — Added two skill guards. `tests/skill-frontmatter-contract.test.ts` now fails when a model-invocable, non-vendored skill's `description` never says when to use it, and separately fails when a hash-locked skill with a frozen upstream description has no `modes`/`do_not_use_for` routing metadata in `registry.json`; its detector is pinned against sample descriptions in both directions so it cannot be loosened into a rubber stamp. `tests/skill-eval-policy-contract.test.ts` makes ADR 005 executable: it fails when a required `evals/evals.json` disappears or parses to zero usable cases, when an eval appears on a skill outside the ADR's tranche, and when an eval is added to a hash-locked vendored tree, where the next sync would silently discard it.
- IPI-1374 · REPO-HYGIENE-001 — Added `npm run supabase:cli` so the local Supabase stack works in a checkout that contains the dotenvx-encrypted `.env.local`. Root cause, bisected rather than guessed: `supabase/config.toml` resolves values through `env(NAME)`, the CLI reads `.env.local` to build that lookup table, and every value in it begins with `encrypted:`, which the dotenvx-aware CLI cannot decrypt because `DOTENV_PRIVATE_KEY_LOCAL` lives in `.env.keys` — a file the CLI never reads. The script injects only those keys through the repository's existing dotenvx boundary (4 keys, not the 64 plaintext values a `--convention=nextjs` injection would add) and `--ignore=MISSING_ENV_FILE` leaves CI on the unmodified upstream CLI. Supabase CLI 2.118.0 was tested against this tree and fails identically, so the 2.116.0 pin stays and the gap is closed in the repository.
